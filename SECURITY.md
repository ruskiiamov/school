# Безопасность

Если вы нашли уязвимость, не заводите публичный issue. Сообщите о ней
приватно через «Report a vulnerability» на вкладке Security этого
репозитория на GitHub. Опишите, как воспроизвести проблему и какую версию
вы проверяли (`server -version`).

Поддерживается только последняя выпущенная версия: исправления выходят
новым релизом, а не патчами к старым. Обновление описано в `README.md`.

Что приложение делает само: пароли хранятся как bcrypt-хеши, сессии
серверные, подбор пароля ограничен по логину и по адресу (знакомые устройства
владельца при этом не блокируются), формы защищены проверкой источника запроса, задан строгий
Content-Security-Policy, файлы отдаются только после проверки прав.
Что остаётся за школой: HTTPS через обратный прокси, `session.secure: true`,
доступ к серверу только по SSH-ключам, регулярные резервные копии и их
хранение вне сервера.
