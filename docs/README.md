# Проектные документы

Документы живут рядом с кодом и правятся в том же PR, что и код, который их
меняет. Они короткие и «живые»: устаревший абзац удаляется, а не помечается.

| Файл | Что там | Когда правится |
|---|---|---|
| `decisions.md` | журнал решений (ADR-lite): что решили, почему, что отвергли | append-only, каждое важное решение |
| `open-questions.md` | открытые вопросы с вариантами; закрытый вопрос превращается в запись в `decisions.md` | постоянно |
| `domain.md` | доменная модель: глоссарий, сущности, связи, инварианты, права ролей, границы (что НЕ делаем), схема таблиц | после закрытия вопросов по домену |
| `scenarios.md` | сценарии по ролям с критериями приёмки — из них пишутся тесты | перед каждой итерацией |
| `ui.md` | экраны, навигация, текстовые макеты | перед каждой итерацией |
| `roadmap.md` | итерации: что входит, что нет, порядок | в начале, потом по факту |

## Процесс

1. **Раунд вопросов.** Открытые вопросы обсуждаются, по каждому принимается
   решение и переносится в `decisions.md` с обоснованием.
2. **Домен.** Когда закрыты вопросы про сущности и доступ — пишется `domain.md`.
3. **Сценарии и UI.** По домену пишутся сценарии с критериями приёмки и макеты.
4. **Итерации.** `roadmap.md` режет работу на вертикальные срезы (схема → сервис →
   страница → тест). Перед каждой итерацией — короткий план реализации, после —
   правка документов по факту.

Нумерация решений сквозная (`D-001`, ...), вопросы ссылаются на решения, которые
их закрыли.
