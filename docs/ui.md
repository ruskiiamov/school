# Интерфейс

Оболочка `layout.App` остаётся: сайдбар слева на десктопе, выдвижное меню на
телефоне. Меню строится по роли (D-033). Все страницы админа живут под
`/admin`, страница смены пароля — `/account/password`.

## Меню

| Роль | Пункты |
|---|---|
| admin | Дашборд `/`, Классы `/admin/classes`, Предметы `/admin/subjects`, Учителя `/admin/teachers`, Ученики `/admin/students`, Родители `/admin/parents`, Типы работ `/admin/work-types`, Замены `/admin/substitutions` (итерация 3), Дневники `/admin/diary` (итерация 4), Сброс пароля `/admin/password-reset` |
| teacher | Дашборд `/`, Журнал `/journal` (итерация 3), Сменить пароль `/account/password` |
| student, parent | Дашборд `/`, Дневник `/diary` (итерация 4), Сменить пароль `/account/password` |

В шапке: ФИО, роль и кнопка «Выйти». У учителя, ученика и родителя
последний пункт меню — «Сменить пароль» `/account/password` (у админа его
нет, D-050).

## Маршруты итерации 2

```
GET  /admin/subjects?inactive=1&edit={id}   одна страница: форма добавления, строки текстом, `edit` — одна строка формой (D-043)
POST /admin/subjects, /{id}, /{id}/deactivate, /{id}/activate
GET  /admin/work-types?inactive=1      то же, плюс POST /{id}/up, /{id}/down — порядок стрелками
GET  /admin/classes?year=2026&inactive=1&edit={id}   список по году как у предметов (D-043, D-044): вкладки-ссылки лет (годы существующих классов и текущий), строка добавления только в текущем году, `edit` — одна строка формой
POST /admin/classes?year=2026, /{id}?year=…, /{id}/deactivate?year=…, /{id}/activate?year=…   класс создаётся в текущем году; `year` в адресе — для списка и редиректа
GET  /admin/classes/{id}               карточка класса: блоки #class-students и #class-assignments, формы только у активного класса текущего года (D-049)
POST /admin/classes/{id}/students      добавить ученика (student_id); HTMX — фрагмент блока, иначе редирект на карточку
POST /admin/classes/{id}/students/{sid}/remove
POST /admin/classes/{id}/assignments   назначить (subject_id, teacher_id); занятый предмет — замена учителя
POST /admin/classes/{id}/assignments/{aid}/remove

GET  /admin/teachers?q=&inactive=1&edit={id}   одна страница: строка добавления, строки текстом, `edit` — одна строка формой (D-047); аналогично /students (+class={id}), /parents; с HTMX форма поиска подменяет `#users` вместе с шапкой
POST /admin/{teachers|students|parents}?q=&class=&inactive=1   создать → /{id}/created; query списка тянется через действия строк и редиректы обратно
POST /admin/{teachers|students|parents}/{id}, /{id}/deactivate, /{id}/activate   → список (HTMX — фрагмент)
GET  /admin/{teachers|students|parents}/{id}/created   логин и пароль один раз (данные — из одноразовой записи под сессией админа, не из URL); повторно — редирект к списку
GET  /admin/parents?edit={id}&child=…   строка правки родителя с блоком «Дети»; `child` — живой поиск ученика по ФИО (D-049)
POST /admin/parents/{id}/children?edit={id}&child=…   добавить (student_id); /children/{sid}/remove — убрать; HTMX — фрагмент #users, иначе редирект на список с теми же edit и child

GET  /admin/password-reset?q=          поиск по ФИО среди активных учителей, учеников и родителей; пустой `q` — пустой список с подсказкой (D-056); с HTMX подменяется `#password-reset`
POST /admin/password-reset/{id}?q=      сгенерировать пароль → /{id}/created?q= с заголовком «Пароль изменён»; админ и неизвестный id — 404
GET  /admin/password-reset/{id}/created?q=   логин и пароль один раз, кнопка «К поиску» ведёт на /admin/password-reset?q=; повторно — редирект туда же

GET  /account/password, POST /account/password
```

Действия, меняющие состояние, — только POST; «удалить/убрать» — кнопки в
форме, не ссылки. Ответы на HTMX-запросы для блоков состава и нагрузки —
фрагмент блока, для детей — контейнер `#users`; без `HX-Request` —
редирект на карточку или список.

│ Ученики                         │ Предметы и учителя        │

На телефоне колонки идут одна под другой: сначала ученики, потом предметы.
Формы «Добавить»/«Назначить» и кнопки «Убрать» есть только у активного
класса текущего года; деактивированные ученик, учитель или предмет
остаются в списке с пометкой «удалён». Пустые блоки: «Пока нет учеников»,
«Предметы пока не назначены»; когда добавлять некого, вместо формы —
«Нет учеников без класса» или «Нужны активные предметы и учителя».
Список классов: под заголовком ряд вкладок-ссылок «2025/2026 · 2026/2027»,
ниже (только в текущем году) строка «название + Добавить» и строки с
«Изменить» и «Удалить», как у предметов; имя класса — ссылка на карточку,
на карточке кнопки «Изменить» нет.

Сброс пароля — отдельная страница `/admin/password-reset` (D-056):
поле «Поиск по ФИО» с живым поиском, как в разделах, список изначально
пустой с подсказкой «Введите ФИО, чтобы найти пользователя». Найденные —
активные пользователи всех трёх ролей, отсортированные по ФИО:

```
┌ Сброс пароля ───────────────────────────────────────────────────────┐
│ [Поиск по ФИО…                                             ] [Найти] │
├──────────────────────────┬──────────┬────┬────────────┬──────────────────┤
│ Иванов Пётр Сергеевич    │ Родитель │    │ ivanov.p   │ [Сбросить пароль] │
│ Иванова Мария Петровна   │ Ученик   │ 7А │ ivanova.m  │ [Сбросить пароль] │
└──────────────────────────┴──────────┴────┴────────────┴──────────────────┘
```

«Сбросить пароль» сначала открывает окно «Сбросить пароль пользователю
Иванова Мария Петровна?» с кнопками «Отмена» и «Сбросить» по центру
(D-053); ФИО в вопросе — чтобы перепроверить, кому сбрасывается пароль.

Страница после создания (и после «Сбросить пароль», с заголовком «Пароль
изменён», кнопкой «К поиску» вместо «К списку» и без кнопки «Ещё»):

```
┌ Ученик создан ──────────────────────┐
│ Иванова Мария Петровна              │
│ Логин   ivanova.m                   │
│ Пароль  Kx7#pq2m   (показан один раз)│
│ Передайте данные ученику.           │
│           [К списку] [Ещё ученика]  │
└─────────────────────────────────────┘
```

Логин и пароль собирает сервер на POST (D-048), JS в форме нет; результат
админ видит на странице «создан». Поле поиска помечено `hx-preserve`, чтобы
живой поиск не терял фокус и ввод при подмене контейнера.

Смена своего пароля `/account/password`: текущий, новый, повтор, кнопка
«Сменить пароль»; у каждого поля пароля (и на входе) кнопка-глаз, которая
показывает набранное (D-053); ошибки под полями, введённое остаётся в
полях (HTMX подменяет только тексты ошибок под полями и блок
`#password-status`, сами поля остаются — D-054); под полями подсказка
«Не короче 8 символов. После смены придётся войти заново на других
устройствах.»; успех — редирект на `?done=1` с зелёным сообщением
«Пароль изменён. Остальные ваши сессии завершены.».

Дашборд админа: «Здравствуйте, {ФИО}» и «Сегодня {дата}», при
отсутствии классов — жёлтый баннер «В 2026/2027 ещё нет классов» с кнопкой
«Создать класс», ниже под заголовком «Учебный год 2026/2027» четыре
карточки-ссылки «Классы · Ученики · Учителя · Предметы» с числами текущего
года. Остальным ролям — то же приветствие и карточка-ссылка на «Журнал»
или «Дневник» с подписью «Раздел в разработке и появится в одной из
следующих итераций»; страницы-заглушки показывают тот же текст пустым
состоянием.

## Маршруты итерации 3

```
GET  /admin/substitutions?ended=1&edit={id}   строчный паттерн (D-043): строка добавления «класс, предмет, учитель, с, по», `edit` — одна строка формой только с датами
POST /admin/substitutions, /{id}, /{id}/delete   → список (HTMX — фрагмент `#substitutions`), `ended` тянется через редиректы

GET  /journal                          форма «Класс · Предмет» + дата + «Открыть», ниже последние 15 уроков; оба в фрагменте `#journal`, форма целится в него
POST /journal                          class_id, subject_id (одно поле `pair` вида `{class}-{subject}`), date → создать или открыть → редирект на /journal/lessons/{id} (HTMX — `HX-Redirect`); ошибка — фрагмент `#journal` или вся страница
GET  /journal/lessons/{id}?student={sid}&mark={mid}   страница урока: шапка, тема, `#lesson` из списка учеников и панели выбранного; `mark` — одна оценка формой
POST /journal/lessons/{id}/topic       тема → редирект на урок (HTMX — фрагмент `#lesson-topic`)
POST /journal/lessons/{id}/delete      только пустой урок → редирект на /journal
POST /journal/lessons/{id}/marks?student={sid}          поставить (work_type_id, value, label)
POST /journal/lessons/{id}/marks/{mid}?student={sid}    править
POST /journal/lessons/{id}/marks/{mid}/delete?student={sid}
POST /journal/lessons/{id}/students/{sid}?student={sid}  отсутствие + комментарий (absent=1, comment)
```

Ответы на HTMX-запросы страницы урока — фрагмент `#lesson` (обе колонки:
отметки слева меняются вместе с оценками), тема — фрагмент `#lesson-topic`;
без `HX-Request` — редирект на `/journal/lessons/{id}?student={sid}`.
Ошибка формы — тот же фрагмент или вся страница со статусом 200 и
введёнными значениями. Кнопка «Удалить урок» и текст ошибки удаления живут
в фрагменте `#lesson-actions` в шапке: форма удаления целится в него, а
каждый ответ с `#lesson` несёт его же через `hx-swap-oob`, чтобы кнопка
исчезала сразу после первой оценки или записи. Переход между учениками — `hx-get` с `hx-push-url`, адрес в строке
браузера меняется.

## Маршруты итерации 4

```
GET  /diary?date=YYYY-MM-DD&child={id}&lesson={id}   ученик и родитель: форма даты (GET, «Показать») и ссылки «Вчера/Сегодня/Завтра», у родителя вкладки детей; фрагмент `#diary` — уроки дня слева и выбранный урок справа
GET  /admin/diary?q=                                  поиск активного ученика по ФИО, как на «Сбросе пароля»; фрагмент `#diary-search`
GET  /admin/diary/{id}?date=&lesson=                  дневник ученика для админа, тот же фрагмент `#diary`
```

Всё только чтение. С HTMX форма даты, ссылки дней, уроков и детей
подменяют `#diary` с `hx-push-url`; без JS — обычные GET-переходы.
Чужой урок, чужой ребёнок, не ученик — 404.

## Состояния

- Пустой список: «Пока нет предметов / типов работ / учителей / учеников /
  родителей», строка добавления остаётся сверху; пустой результат поиска
  или фильтра — «Ничего не найдено». В блоке «Дети» — «Пока нет детей»,
  у поиска ученика без результатов — «Ничего не найдено».
- В текущем году нет классов: на дашборде баннер «В 2026/2027 ещё нет классов»
  со ссылкой на создание класса; список классов — «В 2026/2027 пока нет
  классов».
- Ошибка формы: красная строка под полем, значения полей сохранены.
- Деактивированная запись в списке: серый текст и метка «удалён»; кнопки
  «Удалить» и «Восстановить» (в коде — deactivate/activate, D-018).
- «Удалить» у класса с учениками: ошибка «Сначала уберите учеников из
  класса» у строки, класс остаётся (D-052).
- Дневник: день без уроков — «Уроков в этот день нет»; урок без оценок —
  «Оценок нет»; родитель без детей — «К вашему аккаунту не привязаны
  дети»; поиск учеников у админа без запроса — «Введите ФИО, чтобы найти
